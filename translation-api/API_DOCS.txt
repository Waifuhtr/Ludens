TRANSLATION API - REFERENCE
============================
Base URL: your Hugging Face Space's root URL (e.g. https://<user>-<space>.hf.space)
Version: 2.0.0 (FastAPI app title/version)

AUTHENTICATION
---------------
If the API_KEY environment variable is set on the server, every endpoint below
marked (auth) requires the header:

  X-API-Key: <your key>

If API_KEY is empty/unset (default), no auth header is required.
Missing/invalid key -> 401 { "detail": "Invalid or missing X-API-Key header" }

CONTENT TYPE
------------
All POST bodies are JSON (application/json), except /project/upload which is
multipart/form-data. All responses are JSON except /project/{id}/download
(binary zip).

================================================================================
SINGLE / BATCH / DOCUMENT TRANSLATION
================================================================================

POST /translate  (auth)
  Translate one string.
  Request body:
  {
    "text": "<string>",                 // required
    "target_lang": "<code>",            // required, e.g. "tr"
    "source_lang": "<code>" | null,     // optional, auto-detect if omitted
    "style": "<string>" | null,         // optional, overrides DEFAULT_STYLE
    "glossary": { "term": "translation" } | null,  // optional, merged with server glossary
    "preserve_placeholders": false,     // optional, default false (see note below)
    "context": "<string>" | null        // optional, extra context sent to the model
  }
  200 response:
  {
    "translation": "<string>",
    "elapsed_seconds": <float>
  }
  Notes:
  - If the text has no translatable content (pure control codes / placeholders /
    whitespace), it is returned unchanged with elapsed_seconds = 0.0 and no
    model call is made.
  - On backend failure -> 502 { "detail": "<error message>" }.

POST /translate/batch  (auth)
  Translate many independent strings in parallel (order preserved, no shared
  context between them - use /translate/document for connected dialogue).
  Request body:
  {
    "texts": ["<string>", ...],         // required, min 1 item
    "target_lang": "<code>",            // required
    "source_lang": "<code>" | null,
    "style": "<string>" | null,
    "glossary": { "term": "translation" } | null,
    "preserve_placeholders": false,
    "context": "<string>" | null
  }
  Limit: len(texts) must be <= MAX_BATCH_SIZE (default 200), otherwise 400.
  200 response:
  {
    "translations": [
      { "original": "<string>", "translation": "<string>" | null, "error": "<string>" | null },
      ...
    ],
    "count": <int>,
    "elapsed_seconds": <float>,
    "items_per_second": <float> | null
  }
  Notes:
  - Each item is translated independently and concurrently.
  - A per-item failure sets "translation": null and "error": "<message>" for
    that item only; the rest of the batch still succeeds.
  - Untranslatable strings (control-codes-only, empty) are copied through
    unchanged with no model call, same as /translate.

POST /translate/document  (auth)
  Translate an ordered list of lines from one scene/file. Lines are packed
  into groups so the model can see surrounding dialogue, improving consistency
  versus translating each line in isolation.
  Request body:
  {
    "texts": ["<string>", ...],         // required, min 1 item, ordered
    "target_lang": "<code>",            // required
    "source_lang": "<code>" | null,
    "style": "<string>" | null,
    "glossary": { "term": "translation" } | null,
    "preserve_placeholders": false,
    "context": "<string>" | null,
    "group_size": <int> | null          // optional, default = server GROUP_SIZE (10)
  }
  Limits: len(texts) <= MAX_BATCH_SIZE (400 if exceeded); group_size must be >= 1
  (400 if not).
  200 response (extends the batch response):
  {
    "translations": [ { "original": ..., "translation": ..., "error": ... }, ... ],
    "count": <int>,
    "elapsed_seconds": <float>,
    "items_per_second": <float> | null,
    "groups": <int>,
    "group_size": <int>,
    "regrouped_fallbacks": <int>
  }
  Notes:
  - Lines are chunked into groups of group_size; each group is translated in
    one generation using numbered markers so line order/count survives.
  - If a group's output cannot be safely decoded (wrong count/markers), that
    group is automatically retried one string at a time. regrouped_fallbacks
    counts how many groups needed this fallback - a number that keeps growing
    means group_size is too large for the model and should be lowered.
  - Control-code-only lines inside a group are copied through and excluded
    from the numbered list (they cost the model nothing and add no risk).

Placeholder/control-code handling (applies to all three endpoints above):
  The model (Hy-MT2) reliably preserves control codes, placeholders and
  variables (\V[1], %1, {var}, etc.) on its own. "preserve_placeholders" is an
  optional extra instruction clause and is OFF by default; there is no
  separate validation step that blocks or flags a translation - whatever the
  model returns is what you get back.


================================================================================
RPG MAKER MV/MZ PROJECT TRANSLATION
================================================================================
Workflow: upload a zipped project -> start a translation job -> poll status ->
download the (partially or fully) translated project back as a zip.

Supported project layouts, detected automatically:
  - MV: www/data/*.json
  - MZ: data/*.json  (no www wrapper)

What gets extracted and translated:
  - Map*.json, CommonEvents.json, Troops.json: in-game dialogue only
    (Show Text / Scrolling Text bodies, Show Choices options).
  - System.json: menu/interface terms (terms.basic, terms.commands,
    terms.params, terms.messages, and the equip/skill/weapon/armor/element
    type-name arrays). gameTitle, currencyUnit, switches and variables are
    left untouched.
  - Database files:
      Items.json / Weapons.json / Armors.json : name, description
      Skills.json                             : name, description,
                                                message1, message2
      Enemies.json                            : name
      States.json                             : name, message1..message4
    Database fields are written back verbatim (a two-line description stays
    two lines); only message-box runs get re-wrapped.
  - NOT translated (out of scope): Script/plugin commands, Plugin Command
    calls, Change Name/Nickname/Profile commands, the MZ speaker-name field,
    the `note` field on any database entry (it holds plugin notetags like
    <tag:value>), Actors.json (name/nickname/profile) and Classes.json (name).
  - Identical source strings are deduplicated and translated once, however
    many times they appear in the project, to save GPU time.
  - One project may be translating at a time (single GPU) - starting a second
    job while one is running returns 409. This limit is SHARED with the Ren'Py
    endpoints: an RPG Maker job blocks a Ren'Py job and vice versa.
  - A job is restart-safe: progress is saved to disk and automatically
    resumed if the server restarts mid-run.
  - Uploaded projects are auto-deleted PROJECT_RETENTION_HOURS after their
    last update (default 24h).

POST /project/upload  (auth)
  multipart/form-data with a single field "file": a zip of the project's
  data folder (or a folder containing www/data or data somewhere inside it).
  Max upload size: MAX_UPLOAD_MB (default 200 MB) -> 400 if exceeded or if no
  RPG Maker data folder is found / zip is invalid (zip-slip protected).
  200 response: project status object (see "Project status object" below).

GET /project  (auth)
  Lists all known projects.
  200 response:
  {
    "projects": [ <project status object>, ... ],
    "running": "<project_id>" | null,
    "retention_hours": <int>
  }

GET /project/{project_id}/status  (auth)
  200 response: <project status object>
  404 if project_id is unknown.

POST /project/{project_id}/start  (auth)
  Request body:
  { "target_lang": "<code>" }     // default "tr" if omitted
  Starts (or resumes) translation for this project.
  200 response: <project status object>
  Errors:
    404 unknown project
    503 { "detail": "The model is still loading. Try again in a moment." }
    409 { "detail": "<reason> (project <id currently running>)" } - another
        project is already translating (single GPU slot).

POST /project/{project_id}/cancel  (auth)
  Cancels the currently running job for this project.
  200 response: { "cancelling": true }
  409 if this project is not the one currently running.
  404 if project_id is unknown.

GET /project/{project_id}/download  (auth)
  Rebuilds and returns the project's data folder as a zip, using whatever is
  translated so far. Available at any time, including mid-run: untranslated
  strings keep their original source text, so the download is always a
  playable game, never a broken one.
  Response: binary zip, Content-Type: application/zip,
  filename "<project-name>-<target_lang>.zip" (or "...-translated.zip" if no
  target_lang is set yet).
  404 if project_id is unknown.

DELETE /project/{project_id}  (auth)
  Cancels the job if it is running, then deletes the project and its files.
  200 response: { "deleted": "<project_id>" }
  404 if project_id is unknown.

Project status object (returned by upload/list/status/start):
  {
    "id": "<project_id>",
    "kind": "rpgm" | "renpy",
    "name": "<original filename>",
    "engine": "mv" | "mz",
    "status": "uploaded" | "translating" | "done" | "cancelled" | "error" | ...,
    "target_lang": "<code>" | null,
    "total_units": <int>,          // unique source strings
    "total_slots": <int>,          // total places those strings are written back to
    "translated_units": <int>,
    "percent": <float>,            // translated_units / total_units * 100
    "failed_units": <int>,         // units that errored during translation (backend errors only)
    "unreadable_files": ["<filename>", ...],  // files that couldn't be parsed
    "running": true | false,       // whether this project is the one currently on the GPU
    "files": [
      { "file": "<filename>", "total": <int>, "done": <int>, "percent": <float> },
      ...
    ],
    "error": "<string>" | null
  }


================================================================================
REN'PY PROJECT TRANSLATION
================================================================================
Same workflow as the RPG Maker endpoints, under /renpy instead of /project,
and returning the same project status object (plus three extra fields).

Accepted uploads (either shape):
  - A zip of just .rpy / .rpyc script files, at any depth.
  - A whole game folder. Only .rpy/.rpyc members are ever unpacked, so the
    art and audio cost nothing in time or disk.
  Mobile Ren'Py builds routinely ship with NO .rpy sources at all - .rpyc is
  a first-class input here, not a fallback, and is read on the same pass.

Always skipped while scanning: tl/ (an existing translation), renpy/ (the
engine's own source), cache/, saves/, lib/, __pycache__/, and - important for
projects that ship both - a .rpyc that has a .rpy sibling in the same folder
(the .rpy is read instead; see "Stale .rpyc siblings" below).

What gets extracted and translated from readable .rpy sources:
  - say statements, with or without a speaker:  e "Hello."  /  "Narration."
  - quoted speakers: `"???" "Who goes there?"` - the dialogue, not the name
  - extend statements
  - menu choices and the menu caption
  - screen text: text, textbutton, tooltip, label, caption, alt
    (the FIRST string on the line - later strings are style/action arguments)
  - ANY string wrapped in _(...) or __(...), anywhere in the file, at any
    nesting depth - inside an Achievement(...) constructor, a dict() three
    levels deep in a list inside init python:, a tooltip keyword on a
    button: block, a define. _() is Ren'Py's own "translate this" marker, so
    it is honoured wherever it appears rather than only at statement level;
    only a translate block's own body (someone else's finished translation)
    is excluded even if it happens to contain one. A bare name that merely
    ENDS in an underscore (get_text_ (x)) is not the marker and is left alone.
  - NOT translated: define/default and python code that is NOT _()-wrapped,
    style/transform/image/init blocks, scene/show/play/jump/call/add/use
    arguments, and any existing translate block.
  - Strings that are only markup ("{i}[points]{/i}") never reach the model.
  - A literal using an escape outside \" \\ \n \t (e.g. Ren'Py's `\ ` hard
    space) is left untranslated rather than rewritten.

What gets extracted from a COMPILED .rpyc with no .rpy source:
  - Say and Menu text (dialogue + menu choices) - stored as plain strings in
    the compiled tree, since dialogue is substituted at display time rather
    than evaluated as code.
      Note on how this is read: pickle returns object state in two different
      shapes and Ren'Py uses both in the same game. Screen-language classes
      come back as a plain __dict__, while renpy.ast nodes declare __slots__
      and come back as the pair (instance_dict, slots_dict), either half
      possibly None. A Say node's text sits in the slots half, so both halves
      are merged - a reader that ignores the pair form silently reports zero
      dialogue for an entire script.
  - Screen text: the `text`, `textbutton` and `label` statements, the
    `tooltip` and `alt` properties, and screen titles passed as
    `use game_menu(_("Options"))`. This covers menu buttons and in-game
    interfaces (shop, stats, inventory screens).
      Ren'Py compiles EVERY screen argument into Python source, so a plain
      "Continue" label occupies the same slot as a style name, an action or a
      variable. Arguments are therefore accepted by shape, not position: only
      a bare string literal or an explicit _() / __() marker qualifies -
      never a name, attribute or call.
      Consequently excluded: key "K_F5" (keysym), bare "H"/"Shift+A" (Ren'Py
      writes help-screen key names bare and wraps only the descriptions in
      _()), scroll="viewport" (named use-argument), Preference("text speed")
      and other actions, gui.* / i.caption / title (not literals),
      "[config.version]" (pure interpolation), and {#auto_page}A (a one-glyph
      button label).
  - The reader never executes anything named inside the pickle (every class
    reference resolves to an inert stand-in), and reports the file as
    unreadable rather than returning a partial result if its internal node
    budget is ever exhausted.

Delivery routes differ by kind, because Ren'Py exposes two hooks and each one
only ever sees its own kind of text:
  - say/menu text -> config.say_menu_text_filter (game/hymt_translate.rpy +
                     game/tl/<lang>/hymt_dialogue.json)
  - screen text   -> game/tl/<lang>/hymt_strings.rpy, a
                     `translate <lang> strings:` block - the same table
                     Ren'Py's own "Generate Translations" writes.
A file is only generated when there is something to put in it.

Stale .rpyc siblings (read this if your project has BOTH a .rpy and its
precompiled .rpyc for the same script - common even in "compiled" builds):
  - The .rpyc is never read or double-counted; the .rpy sibling is the only
    source read for that script.
  - BUT: once that .rpy is translated, its .rpyc - still sitting untouched in
    YOUR game folder, since this tool only ever reads it, never writes it -
    no longer matches the new source. Ren'Py can run the stale compiled
    version against the new .rpy once both are installed together, which
    produces crashes with no obvious cause (e.g. "... must return a Text
    object") the moment a translated line is reached.
  - The fix travels with the download: any .rpy that got translated and has
    a .rpyc sibling is listed in "stale_rpyc" (see below) AND in a
    HYMT_DELETE_THESE_RPYC_FIRST.txt file inside the zip. Delete exactly
    those .rpyc files from your game folder BEFORE copying in the translated
    .rpy files - extracting the zip cannot do this for you, since zip
    extraction only adds/overwrites files, never deletes anything. Ren'Py
    recompiles a fresh .rpyc automatically on next launch once the stale one
    is gone.

How translations are applied:
  - .rpy  : written in place, replacing exactly the characters between the
            quotes. Nothing else in the file is touched, so a file whose
            strings all translate to themselves is byte-identical.
  - .rpyc : compiled scripts cannot be rewritten. Their translations are
            delivered instead as:
              game/hymt_translate.rpy          - installs
                                                 config.say_menu_text_filter
                                                 (chaining any existing filter)
              game/tl/<lang>/hymt_dialogue.json - source -> translation map
              game/tl/<lang>/hymt_strings.rpy   - translate <lang> strings:
                                                  block for _() interface text

POST /renpy/upload  (auth)
  multipart/form-data, field "file": the zip. Streamed to disk, so a large
  game folder does not have to fit in memory. Max MAX_UPLOAD_MB (default 200).
  400 if the zip is invalid, oversized, or contains no .rpy/.rpyc at all.
  200 response: project status object.

GET  /renpy                       (auth)  list projects + which holds the GPU
GET  /renpy/{project_id}/status   (auth)  overall %, per-file %, failures
POST /renpy/{project_id}/start    (auth)  body { "target_lang": "tr" }
POST /renpy/{project_id}/cancel   (auth)  stop after in-flight strings finish
GET  /renpy/{project_id}/download (auth)  zip of ONLY the changed files
DELETE /renpy/{project_id}        (auth)  remove immediately

Same status codes as the RPG Maker endpoints (404 / 409 / 503 / 400).

Extra fields on a Ren'Py status object:
  "script_files":   <int>        how many .rpy/.rpyc files were unpacked
  "compiled_slots": <int>        strings that came from .rpyc and therefore
                                 travel via the generated hook rather than a
                                 file edit
  "stale_rpyc":     [<string>]   .rpyc files now stale relative to a .rpy
                                 sibling this run translated - empty until a
                                 download has computed it once; delete these
                                 exact paths from your game folder first

The download contains only files that actually received a translation, plus
HYMT_DELETE_THESE_RPYC_FIRST.txt when stale_rpyc is non-empty, plus
HYMT_INSTALL.txt always.

Where the files go depends on the shape of the upload, which is why
HYMT_INSTALL.txt is generated per download rather than documented once:
  - upload contained a game/ folder -> the zip mirrors that layout; extract it
    over the game's ROOT directory.
  - upload was loose script files    -> the zip has no game/ folder; copy its
    contents INTO <YourGame>/game/, keeping the tl/ structure intact.
Getting this wrong is silent - Ren'Py just ignores translations it cannot
find, with no error.


================================================================================
ERROR RESPONSE SHAPE
================================================================================
All error responses follow FastAPI's default shape:
  { "detail": "<message>" }        (or a validation-error array for malformed
                                     request bodies, e.g. missing required field)

Common status codes:
  400  bad request (bad zip, batch/document too large, invalid group_size)
  401  missing/invalid X-API-Key
  404  unknown project_id
  409  conflict (another project already translating / cancel on non-running project)
  502  the llama.cpp backend failed to respond
  503  model still loading (only on /project/{id}/start)
